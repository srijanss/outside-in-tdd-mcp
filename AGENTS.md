## Research checkpoints

Don't wait for an explicit `checkpoint`/`tdd-research` request or for
`/clear` to be imminent before persisting planning work — a session can end
at any point (crash, `/clear`, running out of context). But be selective,
not exhaustive: call `record_research` only for something that would be
genuinely costly to reconstruct without it — a decision plus the reasoning
behind it, a confirmed research finding, a plan pivot, or a real open
thread — not routine exploration, intermediate tool output, or anything
already recoverable from code/git history. When several such points pile
up in one stretch of conversation, record them in one call, not one call
per point. Keep each entry to a few bullets, not a transcript.

This is what `catch-up`/`session_start` reads to reorient a fresh session,
so a `tdd-start` cycle can pick up from these notes even after context is
lost.
